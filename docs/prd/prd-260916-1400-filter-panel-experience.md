# 筛选区设计定稿

用户于 2026-09-16 明确选择 B。三个方向的设计已定稿：菜系全选／全不选、星级单选，以及主打体验两列等宽布局并去掉按钮数量。网页功能由后续开发 Agent 实现，本次交付包含完整交互、视觉参考、验收要求和可复制的交接提示词。

## 目的与维护入口

筛选区帮助用户直接表达想看哪些餐厅，同时保持分类名称容易识别。结果集合与地图、热力图、统计、搜索定位共用；数量是否出现在按钮里、采用几列等属于可调整的呈现方式。

本文件是本次设计的维护入口，[B 定稿样例](prd-260916-1400-filter-panel-experience.html)是同目录的视觉参考。下载文件夹提供相同样例及本文副本；选型结论、规则和交接状态统一在仓库维护。本文负责后续实现目标，已有发布行为与历史验收记录保留其当时含义。

## 调研依据

- 旧 PRD 与现有 useFilters 都要求至少保留一个菜系。批量按钮实际保留数据里首次出现的菜系；列表另按分类顺序排列，两者可能不同。香港星级榜已复现“第一项显示粤菜，保留的却是意大利菜”。
- 星级事实已由餐厅字段 star_rating 承载；当前可见集合只组合菜系与主打体验。本地七份星级榜的 372 条记录都有 1／2／3 星值；字段合同仍允许缺省，设计需如实处理未知。
- 数量加在主打体验按钮上，菜系列表没有数量。旧版是四个类型选项，当前最多八类主打体验加“全部”，另有图标。
- 当前桌面面板约 280 px，较窄窗口面板约 220 px。三列压缩叠加允许任意断字，在 1280 px 窗口复现两行名称，在 820 px 窗口复现逐字换行。临时移除数字后仍会断字，需要调整排列。

## 交互规则

### 1. 菜系：两个明确的批量动作

菜系与品类继续多选，同组各选项为“或”的关系。标题旁并列“全选”和“全不选”，两个按钮只作用于菜系这一组。

| 当前状态 | 全选 | 全不选 |
|---|---|---|
| 全部已选 | 禁用 | 可用，清空菜系选择 |
| 部分已选 | 可用，选中本榜所有可见菜系 | 可用，清空菜系选择 |
| 全部未选 | 可用 | 禁用 |
| 数据未就绪或本版无记录 | 两个动作都不可用，沿用相应数据状态 | 同左 |

- 单项最后一次取消也生效。全不选后再勾一项，只显示该菜系与其他条件的交集。
- 全选不改变星级、主打体验、城市、年份、榜单或图层模式。
- 所有菜系未选时，结果数为 0，地图与统计同步；菜系区提示“尚未选择菜系。勾选想看的菜系，或点击‘全选’。”
- 菜系仍有选择但组合结果为零时，提示调整当前条件。清楚区分筛选结果为零、版次为空、加载中和加载失败。
- 批量操作使当前按钮进入禁用状态时，键盘焦点保持在本组可用操作或本组内的合理位置。

### 2. 星级：一次点击，只看对应等级

星级榜的筛选区顺序为“米其林星级 → 主打体验 → 菜系与品类”。必比登隐藏星级组，其余结构顺序自然前移。

| 选项 | 结果条件 |
|---|---|
| 全部（默认） | 不增加星级限制，包含星级未标注记录 |
| 一星 | star_rating 恰好为 1 |
| 二星 | star_rating 恰好为 2 |
| 三星 | star_rating 恰好为 3 |

- 四个选项单选，点已选项保持当前选择；无需为了只看一星先取消其他等级。
- 本榜没有某个星级时仍保留该选项。选择后显示正常零结果，并可提示“本榜单暂无三星餐厅，可以选择其他星级。”数据缺省不能推断成某一星级。
- 必比登的 0 属于不适用，不显示成“零星”选项。
- 组间取交集：星级条件且主打体验条件且菜系条件。主打体验继续“全部或一种类别”单选。
- 当前基线按恰好一个星级设计；组合“一星加二星”等多选行为未纳入本稿。

### 3. 切换、搜索与其他消费端

- 切换城市、年份、榜单后，菜系恢复全选，星级与主打体验恢复全部；单纯切换桌面／手机布局不重置条件。
- 分类显示集合和顺序依据本版全部记录确定，选择星级或另一分类后保持稳定，避免选项随操作消失或跳位。
- 搜索范围沿用本版完整数据。选择被筛掉的餐厅时，启用其菜系；主打体验或星级有冲突时，分别恢复该组“全部”，使目标可见。
- 搜索命中无坐标记录仍能打开详情。已打开餐厅被筛掉后，详情与选中状态按现有规则同步撤下。
- 可定位资格在筛选结果上派生。结果餐厅数和可定位数分别表达，地图、聚合、热力图、区域统计消费同一套筛选结果。

## B 方案视觉规则

采用用户选择的 B 方案，使用现有深色面板、金色选择态、主打体验图标和菜系颜色。分类名称复用现有定义，保留“面饭面点”“日式会席”等完整名称。

| 内容 | 定稿表现 |
|---|---|
| 主打体验 | 矩形圆角选项，两列等宽，按既有固定顺序排列 |
| 窄面板 | 当两列无法容纳完整图标、名称和选中标记时，整组切成一列 |
| 手机 | 宽度足够时仍是两列；按实际面板空间决定列数 |
| 最后一行 | 只有一项时左对齐，保持正常列宽；一列布局自然占满一行 |
| 选中状态 | 金色底及勾号，选中标记预留空间，按钮宽高不因选择改变 |
| 图标与名称 | 图标在左、完整名称在右；同行选项等高 |
| 数量 | “全部”和各主打体验均去掉数字；结果数保留在结果摘要 |
| 菜系 | 桌面和手机使用样例中的复选列表，包含复选框、色点和名称 |

### 阅读、触控与滚动

- 正常字号下，主打体验名称作为完整短语呈现。主打体验最多两列；需要更大空间时改为一列，切换选择时尺寸和位置保持稳定。
- 保留文字、类别图标与明确选择状态。键盘可操作，焦点可见，选择含义同时通过非颜色方式传达。
- 星级、主打体验和批量按钮至少 44×44 CSS px；手机菜系整行点击区域至少 44 px 高。文字放大或空间不足时允许重新排列；长菜系名称可以自然换行，内容仍完整可读。
- 筛选区使用可滚动的整体面板，长列表随整个面板滚动。两列规则只用于主打体验；星级为四项单选，菜系为复选列表。手机菜系行的触控高度至少 44 px。
- 样例在 280 px 面板展示两列、220 px 展示一列、380 px 展示两列。这些是视觉参考宽度，具体断点与 CSS 方法由开发依据内容和缩放验证。
- 当前结果数继续放在结果摘要，与本榜收录量区分。地图可定位数不替代结果数。
- 去掉主打体验按钮数量及其计数说明，仍可根据本版记录判断哪些类别有数据。诊断及其他有独立用途的分类统计继续按原有口径计算。
- 菜系的批量操作紧邻组标题。主打体验与星级为单选，不套用“全不选”。

### 用户选择

2026-09-16，用户反馈“我最喜欢B”。本稿据此锁定 B 及其去数量方案。整齐、稳定的排列优先于尽量少占高度；窄面板一列的额外滚动由整体面板承接。开发阶段据本节直接实施。

## 可观察验收

| 场景 | 应观察到的结果 |
|---|---|
| 全选 → 全不选 → 只选一个菜系 | 全部 → 0 → 对应交集；最后一项可取消 |
| 部分菜系已选，执行批量操作 | 两个动作各自确定，星级和主打体验不变 |
| 全部／一星／二星／三星 | 匹配对应等级；全部保留未标注记录 |
| 成都选择三星 | 明确零结果，可恢复其他等级 |
| 二星＋法式＋指定菜系 | 地图、可定位数、统计与详情一致 |
| 筛选后选择搜索结果 | 必要筛选组被放开，目标显示或打开无坐标详情 |
| 切换版次或榜单 | 条件恢复默认；必比登隐藏星级组 |
| 窄面板与类别最多的榜单 | 宽时两列、窄时一列，名称完整，最后一项不拉宽，选择态不造成位置跳动 |
| 主打体验数量 | 所有选项含“全部”均没有数量，结果摘要仍正确 |
| 手机与文字放大 | 触控目标、焦点、完整文字与滚动可用 |
| 加载中、空版次或失败 | 使用对应数据状态，不误报为用户全不选 |

布局验收覆盖桌面 1280×800、较窄窗口 820×1000、手机 390×844、窄手机 320×640，并检查 200% 页面缩放。逐项检查标签、触控目标和滚动可达性。按 B 方案在 Chromium 与 WebKit 验证；本次独立样例检查不替代生产应用验收。
