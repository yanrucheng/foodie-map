# 主打体验图标与价格角标：设计定稿

状态：用户已确认视觉样例、八类融合规则、价格直接使用 ¥ 符号、缺价不显示角标，并授权完成工程与 runbook 设计。本文定稿；产品代码尚未开发，开发和独立验收见 [tasks](tasks.md)。

## 1. 目的、范围与非目标

帮助用户在地图上快速判断“主要来吃什么、属于什么菜系、价格在哪一档”，并让新增地区的 Agent 按同一规则提供数据。图标分组的分散程度用于评价产品分类是否有用，不要求每城或每榜单的八类数量相等。

| 通道 | 确定含义 | 权威输入 |
|---|---|---|
| 颜色 | 菜系与品类，沿用 P08 现有范围 | cuisine_group；完整 cuisine 与 taxonomy/mappings 保留 |
| 主图标 | 八类主打体验，一店一个主值 | 新字段 dining_category |
| 价格角标 | 来源的相对价格等级 | price_range；显示 ¥、¥¥、¥¥¥、¥¥¥¥ |
| 文字 | 名称、精确原始标签、分类含义、价格原文与来源 | 既有字段和共享事实适配 |
| 外圈、NEW、聚合数 | 选中/焦点、年度新晋、筛选后的可定位数量 | 既有状态与集合 |

图标采用食品与综合料理相结合的产品分类，不承诺与颜色严格正交。继续使用“菜系与品类”描述颜色，避免把寿司、拉面等现有色组误称为纯风格。

非目标：全量正式补标、自动菜单推理、按名额均分类别、菜系同义 key 清理、每城不同图标表、价格筛选/换算/预算推断、新分析仪表盘、地图投影或热力图算法变更、真实发布。

## 2. Backward Compatibility Policy

继承 [BC-01](../../../docs/plan/plan-260913-0040-frontend-professionalization.md#6-backward-compatibility-policy) 与 [P08 的增量边界](../p08-automatic-visual-encoding/design.md#2-backward-compatibility-policy)。生产使用范围、外部 JSON 消费者和退役等级仍未进一步确定；本包不需要决定旧接口退役，故不阻塞设计或本地实现。

| 项目 | 本包确定的处理 |
|---|---|
| 字段 | 增加可选 dining_category；原 serving_form、venue_type、价格/币种及其他事实保留原义、原值和原校验 |
| 界面 | 采用已获用户确认的新图标和主打体验筛选；不同时保留两套类型筛选 |
| 链接与文件 | 保留合法 year/city/guide 语义、catalog、年度文件及固定年度 legacyPath |
| 旧客户端 | 沿用 P07 整包、不可变资源和摘要校验，验证旧/新资源不混读；不清缓存冒充兼容 |
| 兼容机制 | 不假定 L0 或永久 L3；不增版本路由、双写、旧类型到新类型适配器或切换 feature flag |
| 退役 | 删除旧字段、旧公开 URL 或真实迁移发布另归 BC-01；不纳入本包 |

保留旧字段是保留已经有不同含义的事实。新字段不会被当作旧字段别名，也不要求后续 Agent 同时补齐三种分类字段。

## 4. 数据合同与八类映射

### 4.1 新字段

增加 `dining_category?: DiningCategory | null`。合法业务值恰为下表八个；一个门店记录只有一个值。类别之间的经营判断遵循 runbook，不由浏览器分析名称、菜单或原始 cuisine。

| 值 | 显示名 | 固定图形 | 素材 |
|---|---|---|---|
| staple | 面饭面点 | 碗筷 | Tabler bowl-chopsticks |
| meat | 肉食主打 | 肉块 | Tabler meat |
| seafood | 鱼鲜主打 | 鱼 | Tabler fish |
| dessert_drink | 甜饮 | 蛋糕卷 | Tabler cake-roll |
| french | 法式 | 厨师帽 | Tabler chef-hat |
| chinese | 中餐 | 锅 | Lucide cooking-pot |
| japanese_course | 日式会席 | 多器皿餐盘 | 已确认预览中的本地自绘 SVG |
| other | 其他料理 | 刀叉 | Tabler tools-kitchen-2 |

顺序固定为表格顺序。`dessert_drink` 同时覆盖甜品与饮品主打，咖啡等不要求甜味；`japanese_course` 对应用户接受的会席、怀石及同类多道和食套餐宽口径。仅有“日本料理”、星级或高价格不能证明后者。

预览内部键 `sweet`、`kaiseki` 是样例实现细节，正式值分别为 dessert_drink、japanese_course；其他键同表。只从预览取图形和视觉规则，不从它自动迁移数据，不建立这些预览键的兼容别名。

### 4.2 缺省、other 与非法值

| 输入 | 校验 | 图标/详情/统计 |
|---|---|---|
| 八个合法值 | 通过 | 显示固定图标和名称；other 是显式归类 |
| 缺省或 null | 通过 | 通用刀叉，保留菜系颜色；详情注明“主打体验未标注”；统计单列 unclassified |
| 空串、unknown、mixed、旧 meal/snack、数组、数字等 | 错误 | 定位文件/id/字段，使用既有整份数据集可恢复错误态；不静默变 other |
| 仅有 serving_form 或 venue_type | 旧字段按原合同校验 | 新主分类保持未标注，不自动转成任何八类 |
| 新旧字段并存 | 分别校验 | 新主图标和筛选只消费 dining_category；不要求不同含义的字段值一致 |

数据里的 other 用于有依据的未单列料理；证据不足或尚未判断时留空/null。两种情况可以共用刀叉图形，但不能混作“已标注”。它们与用于颜色的 cuisine_group=OTHER 也彼此独立。

不再显示问号主图标，不存 unclassified 业务值，不为图标增加 confidence、per-record SVG 或颜色覆盖字段。现有记录禁止 color/icon/svg 的合同继续生效。

### 4.3 数据判断的自动化边界

Agent 从可用材料判断主打体验，字段在数据准备时确定。足够明确的“拉面”“寿司”等来源标签可以支持对应食品主打；完整原文和判断依据保留。食品主打优先于综合料理，不以营养占比计算，也不要求只卖一种食品。

日式多道和食需要经营/菜单/菜序依据。复合“本帮菜/点心”仅是线索，不能运行时或批量按“含点心”直接判 staple。本规则取代预览对 7 条复合标签的快速试分捷径；预览统计不是需要维持的目标数字。

旧 dessert/drink 等事实可供 Agent 查阅并复用已有来源，但程序不根据它们填新字段。boarding 继续仅改变 cuisine_group，对 dining_category 和所有原始事实原值透传；不把主打判断藏进 boarding。

## 5. 价格等级角标

### 5.1 解析与输入边界

复用 price_range，不增加持久化 price_tier、badge_text 或 currency 转换字段。共享纯函数将源价格等级解析为 1–4 或无可用等级，供地图、详情、统计与 Node 校验共同使用。

确定的解析规则：

1. 缺省/null、空串或仅空白为 missing，返回无等级。
2. 仅在解析副本上 trim 和 NFKC 规范化；原始字段字节不变。
3. 规范化后由 **1–4 个相同的 Unicode 货币符号**组成时，按字符数得到等级。可用 Unicode Sc 类别判断；必须拒绝混合符号。此规则同时支持现有 ¥、全角 ￥、港澳 $，也可承接 €、£ 等来源等级。
4. 其他非空文本为 unrecognized。仍保留合法字符串事实、在详情显示原文，在诊断中汇总/指出，角标不显示。非字符串继续由原 schema 拒绝。
5. 角标只输出 `¥`.repeat(等级)。$ 转成 ¥ 是等级图形的统一显示，不是货币或金额转换；currency 与价格原文不变。

| price_range 输入 | 角标 | 处理 |
|---|---|---|
| ¥ / ¥¥ / ¥¥¥ / ¥¥¥¥ | 同样数量的 ¥ | 有效等级 1–4 |
| $$ / ￥￥￥ | ¥¥ / ¥¥¥ | 同级显示，保留源文 |
| 缺省 / null / 空白 | 无角标元素 | missing |
| ¥150–250 / 150 / 约200元 / ¥¥¥¥¥ / $¥ | 无角标元素 | unrecognized；不按符号数或数字猜等级 |
| 只有 price="150–250"、currency="CNY" | 无角标元素 | 真实金额不能推导相对等级 |

角标固定使用符号，不提供 P1–P4 切换器；缺失不创建空角标、P—、问号、横线或透明占位框。图例说明“¥ 数量表示价格等级，非金额；跨城市不代表相同预算”。

### 5.2 与详情的关系

保留 P02 的 price/currency 原文显示规则。详情可同时展示实际价格文本与价格等级，不以角标替换原始金额。价格等级缺失且也无实际价格时，可以在详情说明“价格未提供”；点位本身保持简洁。price_range 有非标准原文时仍可在详情查看。

首版不增加价格筛选、排序、均价或聚合点价格。等级不会改变图标、颜色、地图位置、过滤集合或星级。

## 6. 展示、交互与本地素材

### 6.1 确定性与素材

继续使用 P08 FNV-1a 32 位 over canonical ASCII cuisine_group，hue=hash%360、62% 饱和度、28% 亮度、白色前景；OTHER=#666666。不得为新图标重排颜色或合并同义 key。

八项展示定义通过 Record<DiningCategory, ...> 或等价穷尽检查保证完整。新增菜系只走 taxonomy/mappings；新增地区不在展示模块增加城市分支。合法新 key 不需要手写颜色。

[preview.html](preview.html) 保存用户确认的图形和符号角标；源文件 SHA-256 为 `368eb70a555d2e72b141ae4206ddcce417d5a338c03a8c455627279f72869d1f`。图标采用其中 Tabler Outline 3.46.0、Lucide 1.46.0 和自绘餐盘；保留对应许可及来源。厨师帽/锅/餐盘的类别含义是产品图例约定，不声称社区有统一的菜系符号标准。

开发时提取所需的八份本地 SVG/path；不依赖 Downloads、临时目录、整个预览脚本或外部 CDN。React 与 Leaflet 共用受信静态图形。可将资源内联或随构建打包；供 Node 使用的定义不能依赖 DOM、React、Leaflet 或 Vite 专属导入。

### 6.2 标记尺寸与状态

- 以已确认预览的 36px 圆底、约 21px 图形、24×24 viewBox、1.8–1.9 线宽作为起点；命中目标至少沿用约 44px。中心锚点始终是原有投影后的餐厅坐标。
- 价格角标位于右上外缘，浅色不透明底、深色字、细边沿，单独承载 1–4 个 ¥；起点为约 10px 字号、16px 高度，宽度随文本。正文图标不被覆盖，四个符号不截断。
- 将既有 NEW 移至圆底下方的独立小徽标，继续由 is_new/edition_year 决定；不得与右上价格互相遮挡。详情仍保留年度新晋文字。
- 选中和键盘焦点继续用外圈/层级表达；价格、图标和颜色同时保留。辅助角标不成为第二个独立交互目标。
- 沿用高缩放仍可聚合与 spiderfy；密集/同坐标点展开后能选中。不得为了布局挪动餐厅坐标，也不靠额外透明覆盖层抢夺邻点点击。
- 混合聚合点只显示筛选后可定位数量，既不取某店图标，也不取平均/最贵价格；热力色阶保持原义。

尺寸和间距允许开发者根据实际 Leaflet、移动端、缩放和中英文标签验证局部调整。语义、锚点、可操作性及所有符号完整可读是硬约束。角标文字对比至少 4.5:1；图形和边界沿用 P06 可测对比要求。

### 6.3 筛选、图例、两端详情与计数

2026-09-16 后续设计：[筛选区 B 定稿](../../../docs/prd/prd-260916-1400-filter-panel-experience.md)已接替本节的控件布局、筛选组合与按钮数量展示要求，新增星级筛选并去掉主打体验按钮数字。下表保留 P09 初始设计记录；分类身份、未标注处理、图标、价格角标及诊断计数口径仍由 P09 负责。新筛选设计已定稿，网页实现另行交接。

| 消费端 | 行为 |
|---|---|
| 主打体验筛选 | 替代四类消费形式控件；默认全部，单选一种主分类，并与菜系筛选做 AND |
| 类别按钮 | 名称、图标及数量共用定义；以整份当前城市/年度/榜单数据计数，含无坐标记录；按固定顺序显示有记录的类别 |
| 其他料理 | 作为一个展示过滤组，包含显式 other 与缺省/null；筛选按钮只显示类别名和合计数量，不附未标注数量或括号说明；数据诊断仍分清两种状态 |
| 全部未标注 | 仍可浏览/搜索，使用正常菜系颜色和通用刀叉；筛选区只显示“全部 N”“其他料理 N”，未标注状态保留在数据和诊断中 |
| 图例 | 说明颜色=菜系与品类、图标=主打体验、角标=价格等级；复用类别控件的符号表，不铺第二份长分类列表 |
| 详情 | React 与 Leaflet 共用 category、标注状态、原始 cuisine、颜色、价格等级/原文；未标注与显式 other 的文字不同 |
| 搜索揭示 | 对被过滤命中的记录启用其菜系，按需恢复主打体验过滤；无坐标记录仍能看详情 |
| 切版与选择 | 保留现有数据集隔离、外圈和详情同步撤下；不把上一城市/榜单的过滤或选中记录留在新集合中 |

显示数量、地图、聚合、统计和热力图来自同一过滤结果；可定位只是地图资格，不影响主分类的“全部收录”计数口径。

点位 accessible name 包含餐厅、菜系、主打体验或未标注状态、有效价格等级以及适用的新晋信息。价格等级可以读作“价格等级 3，共 4 档”，视觉仍为 ¥¥¥；不依赖 hover、颜色或图标单独传达含义。

## 7. 自动化与分布诊断

复用 validate:data 与既有发布管线，不新建 CLI 或实时分类器。纯共享函数在浏览器、校验和测试中统一使用。

| 统计 | 精确定义 |
|---|---|
| counts.dining_category | 八个业务值的显式记录数，加 unclassified（缺省/null）；九个计数之和等于 listed |
| UI 八类计数 | 与上项同源；展示 other=显式 other+unclassified，八类合计等于 listed |
| counts.price_grade | 1、2、3、4、missing、unrecognized 六类，合计等于 listed |
| 最大图标组占比 | max(UI 八类数)/listed；空名单返回无比例，不生成 NaN |
| 最大同图标同价位组占比 | 按“展示类别×有效等级/无角标”分组的最大数量/listed；missing 与 unrecognized 同为无角标组合，源诊断仍分别保留 |

每个城市×年度×榜单提供数量与最大组信息；城市合并结果可额外汇总，但必须保留分榜单结果。价格组合的改善不能被描述为图标本身变均匀，也不等于屏幕遮挡率、辨识率或用户测试。

保留当前 counts.serving_form 及来源/位置诊断，增加新统计即可，不在本包退役旧报告字段。新增主分类非法值按既有 error 定位；缺失只汇总，不逐店制造 warning。非标准非空 price_range 可按既有诊断模型报告 UNRECOGNIZED_PRICE_GRADE warning，源文仍保留且记录继续可用。

不设最低补标率、最大 other 占比或八类均分门槛。有效分类支持齐全、非法值可见、统计可核对是工程门禁；真实经营判断由 runbook 和数据任务负责。

## 8. Runbook 与迁移设计

### 8.1 职责分工

| 角色 | 本轮交付 | 不应混作完成 |
|---|---|---|
| 本次设计 | 技术、语义、验收、入口与已确认预览 | 不代表代码支持或正式数据补标 |
| 开发 Agent | schema、统一渲染/过滤、诊断、隔离夹具、runbook 命令联通、回归证据 | 不复制预览试分，不顺手重新标注正式餐厅 |

### 8.2 实施顺序

1. 读取当前工作区和 P09，不覆写东京正在进行的来源修订。保存要保护的正式字段/文件基线。
2. 增量实现 schema、共享展示/价格函数、诊断、统一过滤与所有消费者；更新受影响旧测试，历史四类业务值仍按原合同合法。
3. 用隔离夹具覆盖八类、新旧字段共存、未标注、四种价格和缺价/非标准价格、NEW、同坐标展开及跨数据集切换。
4. 演练现有 boarding 的输入/输出隔离、dry-run、失败不破坏输出，以及新字段/价格原值透传。通过正式 catalog 装载隔离的新城市/年度，无业务城市分支。
5. 将 readme/data-onboarding-guide.md 与本 runbook 的“P09 代码待实现”状态改成实际支持，联动 readme/development.md 和 skills/cuisine-boarding/SKILL.md；这些入口只指向同一规则。
6. 运行受影响检查和最终既有发布门禁，提交实现证据；本地完整产物可用于验收，不推送/部署。
7. 数据 Agent 另行补标并报告真实分布。若准备上线前仍无新字段，所有正式点位会归为通用图标；应报告这一事实，不能以隔离样例的分布声称真实升级完成。

671 条现有记录均尚未补新字段是已知数据工作，不阻塞框架设计/开发，但会限制真实用户可见的区分度。Tokyo 已补的 serving_form 是可复用的来源背景，不是 dining_category 的迁移规则。

### 8.3 唯一接入路径

语义和证据写进[既有来源 runbook](../../../docs/runbook/runbook-260507-1013-valid-data-source-guide.md#p09-labeling)；命令、catalog、aliases、覆盖摘要和版本对账继续使用[既有接入指南](../../../readme/data-onboarding-guide.md)。仓库内 cuisine-boarding SKILL 只指向这些规则并说明它仅改 cuisine_group，不再维护独立分类表。

runbook 固定主分类含义、食品优先规则、缺失语义、源价格和交接结果；采集工具、查阅方式、候选分析和证据组织可由 Agent 选择。已有任务材料足够时直接引用，不强制新增每店证明文件或独立服务。

## 9. 验收与开发者可决定的事项

规范场景见 [P09-R1–R9](specs/dining-experience-markers/spec.md)，执行与证据归 [tasks](tasks.md)。开发者按变更选择受影响快速测试，最终复用 release:check/verify 对同一构建覆盖合同、覆盖摘要、浏览器、性能和离线升级；不先重复跑多轮完整构建来凑次数。

固定：八个值和语义、共享映射、颜色稳定性、只读源价格、无缺价占位、主分类与缺失统计、事实保留、单一接入路径及验收结果。

开放：纯模块的合理拆分、SVG 嵌入方式、测试夹具组织、组件内部命名、在验收约束下调整像素/间距、采集和分析方法。没有等待用户重新选枚举、图标或全局 BC 等级的设计阻塞；不得把实现方法问题重新扩大为产品重设计。
