## Context

既有接入合同声明 WGS84，前端使用高德瓦片并执行 WGS84→GCJ02。当前矩形范围也包含香港/澳门/台湾；本地函数位移不等于已证实的屏幕定位误差，不能在未核验瓦片规则时直接按行政地区改算法。

## Goals / Non-Goals

**Goals:** 以证据决定坐标转换；所有空间操作一致；未核验点不误导；地图和定位资源生命周期正确。

**Non-Goals:** 更换地图供应商作为默认前提、导航规划、后台位置采集、修完每家餐厅的真实坐标、用一个全局矩形推定所有地域的坐标合同。

## Backward Compatibility Policy

按[总计划 BC-01](../../../docs/plan/plan-260913-0040-frontend-professionalization.md)处理。保持用户可用的地图行为；历史错误坐标修订必须按 P02/P03 留下理由，不能把修正静默写成旧版原始事实。

## Decisions

- 规范化存储沿用 WGS84；源坐标为 GCJ02 等时需有来源和转换记录。未知源坐标系不伪装成 WGS84。按本轮用户明确的 P02 合同，未提供空间上下文沿用现有 WGS84 存储约定；缺省/null 的 geocode_success 不否定合法坐标，false 明确禁止。不会增加逐记录认证字段作为绘图门槛。
- 瓦片所需投影/偏移依据供应商资料与实测锚点确定；同一处负责投影，防止标记、热力图和 GPS 各转一次或采用不同规则。
- 数值回归用有来源的坐标对；底图端到端核验用有明确位置证据的锚点。大陆、香港、澳门分别提供至少 3 个空间分散锚点，覆盖现有坐标域；新增域需补证据。
- 数值坐标对转换误差预算为 10m；地图与核验位置的端到端误差不超过既有接入指南的 200m 标准。锚点自身证据精度不足时不能宣称通过，需换锚点或说明未核实。
- 共享 P02 的可靠位置判断；名单层保留未知位置，地图层只显示符合合同的点。
- 地图可以复用或重建，验收只要求活动资源正确、旧回调不影响新视图。定位请求只在用户主动开启时触发，停用/卸载后释放。
- 地图瓦片与数据加载是不同故障，界面应能够说明其中哪个不可用。

## Risks / Trade-offs

- [把供应商坐标规则猜错] → 先保存证据与校准结果，再决定修复方式。
- [重复转换产生数百米偏移] → 全部空间入口用同一组参考点核验。
- [地图重建后定位还绑定旧实例] → 覆盖带定位状态的城市切换、卸载和迟到回调。
- [在线核验不稳定] → 数值与状态回归离线可复现；在线锚点核验保存来源与条件，不进入快速集。

## Migration Plan

确认源/规范化/瓦片规则，建立锚点证据并修正投影入口；接入共享有效性规则；验证生命周期和故障恢复。没有证据的旧坐标保持未核验，不在本包批量改成成功。真实底图校准证据交接给 P07 发布验收。

## Open Questions / Delegated Choices

高德瓦片在各坐标域的实际规则仍需证实。地图复用策略、投影实现库及资源封装由开发 Agent 选择；不得把未经核验的地域假设当作已通过标准。


## Implementation decisions — 2026-09-13

### Spatial contract and ownership (P05-R1/R2/R3)

`src/utils/mapPosition.ts::projectMapPosition(record, spatialContext?)` 是应用唯一 WGS84 → 当前高德显示经纬度边界。它先调用 P02 `getMapPosition`，无资格时返回 null；成功后才执行 gcj02 数值转换，返回有显示坐标类型标识的 `[lat, lon]`。Leaflet 再将显示角度映射到 EPSG:3857 像素，这不是第二次 GCJ 转换。标记、热力、中心、搜索飞行、用户点/精度圈、用户首次飞行都通过此边界。

沿用 P02 的数值、范围、成对、零点、明确失败和显式 unknown 语义；不放宽 payload 校验，不以地图过滤代替数据错误态。未知记录仍由 P04 名单/详情保留，重复坐标不去重。可定位只表示符合当前合同，不表示每条餐厅已完成实地精度核验。中心不合法/上下文 unknown 时采用不声称属于该城市的中立世界视图，并显示空间信息不可用；不飞向未核验中心。

`CityConfig.spatialContext?` 仅扩展当前发现适配器的类型，未改真实城市或坐标。App 将同一上下文传入 useFilters、全量可定位计数、MapShell、桌面未知详情与移动详情。P04 的 restaurants、visibleRestaurants、groups、requestKey、搜索 reveal 和详情身份保持原职责；本包不新增活动数据集状态。正式 P03 catalog 尚未联调，不能把隔离 registry 证明为正式 catalog 验收。

gcj02 的数值与历史范围保持不变；去掉“范围等于大陆行政界线/港澳不受影响”的错误注释。新获取的供应商说明与实际 style=8 瓦片支持当前样本继续转换，尚不构成全地域精度认证。相关历史取证输出已清理，当前精度需重新实测。

### Map and overlay lifetime (P05-R4)

地图在中心、zoom、布局控件或空间上下文变化时可重建。初始化 effect 使用稳定的 attachTo；已删除 P01 的 Hooks lint 临时豁免，没有增加其他禁用。销毁顺序为结束定位会话、卸载定位控件、解绑瓦片事件/计时器、移除热力/聚合点、停止地图动作、销毁地图并清空引用/portal。位置管理器明确绑定一个地图实例，不复用已经销毁的地图。

Leaflet 1.9.4 Canvas 精度圈在快速销毁后可能执行已排队重绘；精度圈改为管理器自有 SVG renderer，随圈释放。leaflet.heat 0.2.0 的 onRemove 不取消 pending animation frame，因此 HeatLayerManager 在移除前取消该图层的 `_frame`；此版本细节局限在图层生命周期，不修改 P01 的装载适配器。

搜索继续尊重 P04 的 visibleRestaurants 引用身份检查。桌面在已确定的坐标直接打开同一记录的 popup（autoPan=false），移动端由 P04 已选中详情卡显示；不再调用 markercluster.zoomToShowLayer 留下无法取消的 moveend/spiderfy continuation。重放发现该 continuation 在旧 marker 被清除后会抛异常。地图关闭 fadeAnimation，使数据集切换时旧 popup DOM 同步撤下，不保留 200ms 淡出残影。手动点标记仍使用原绑定 popup。

所有从 heat 转 marker 的路径均通知 onModeChange，包括搜索定位；MobileShell 按同一模式更新按钮。

### Fixed-deadline location session (P05-R5)

本次用户明确的产品行为：

- 仅点击定位按钮启动；从该次主动开启时刻计算，最多 5 分钟。
- GPS、精度、方向更新和普通 React 重渲染都不延长 deadline。
- 后台停止 watch/方向监听并移除旧定位图层，deadline 继续推进。
- 回前台仅仍有会话且 Date.now() < deadline 时恢复；不重新请求方向权限。
- 手动停止、定位失败、到期、地图销毁或组件卸载结束会话；到期后可再次主动开启。
- 每次 start/stop 对定位 watch 和方向授权各有 generation 防护；过期成功、失败、授权、计时器回调都不能影响新会话。
- 获取位置失败时立即清除点与精度圈，按钮回到可开启状态；拒绝/超时/不支持有持续可读提示，不自动重试或循环申请权限。
- 位置不动但 accuracy 改善也更新精度圈。accuracy 必须有限非负，单位是米；它不是底图校准误差。
- 只显示有效 webkitCompassHeading 或 absolute=true 的 alpha；相对 alpha、无效方向、拒绝或不支持时不显示方向锥。方向权限失败不阻止位置浏览。

useGeolocation 和 useDeviceOrientation 只拥有浏览器订阅与迟到回调防护；useLocationTracking 拥有用户会话、deadline、前后台规则、地图绑定及反馈。移除原依赖易变 hook 返回对象并 setState 的错误 effect 循环。

### Tile service state (P05-R6)

TileService 独立拥有当前 tile layer、监听和失败判定计时器。一个加载批次至少 3 张失败、尚无成功且持续 1500ms 才显示不可用；单张失败不会将整项服务或数据集判错。任何当前层成功事件恢复 available，重试创建新图层、清理旧层事件和计时器。旧层事件不会改新层状态。

阈值是明确的故障展示策略，不是供应商可用性测量。部分失败夹杂成功不报整体故障；悬而未决且没有 tileerror 的网络请求不由该阈值判定。提示与餐厅加载错误独立，按钮不会重载餐厅或重新授权定位。提示位于图例上方且可实际点击；保持 P04 名称、筛选、搜索及详情可用。

### Evidence boundary

快速集使用真实 React 和 Leaflet 对象、假时钟及受控传感器；jsdom 的热力 canvas 输入被替换以验证点集，真正热力绘制交给生产浏览器。浏览器使用生产 Vite 构建和真实 Leaflet/plugins，registry/data/taxonomy 采用明确 fixture，传感器 stub，瓦片失败或用 synthetic SVG 响应，SW 绕过。它们证明实现行为，不证明真实位置精度。

在线空间材料另存实际高德瓦片和公开锚点。10 个候选（大陆4、香港3、澳门3）均记录来源/日期/原坐标/预测坐标；没有把预测值当独立参考。第三方公开数值例子的差值为0m，但三个域独立高精度转换对和实地端到端测量仍未完成；P05-R1 不标通过，最终判定留验收 Agent。

## Supplemental verification — 2026-09-14

P03正式catalog已接通：本轮通过未修改原始catalog与年度文件的生产release构建验证13个名单×2布局，以及隔离原始catalog的unknown负向场景；不再将P03联调列为当前阻塞。该轮测试原始输出已清理。未新增活动数据集、位置资格或供应商注册规则。

东京当前明确WGS84空间上下文沿同一入口，已有数据经度139.57–139.82使当前实现保持原数值；此项是代码行为，不是供应商独立校准证明。东京塔、晴空塔、新宿站真实应用z17中各24张瓦片均为同一179字节纯色PNG；跨4子域、z12/15/18的36次抽样一致。当前style=8在这些样本上无可测量地物，因此东京端到端精度不能验收。HTTP200表示传输成功，不代表地图覆盖；不把单张纯色作为全球故障判据，也不将源坐标改unknown掩盖覆盖问题。本轮没有改供应商或转换算法。

在线证据工具注入公开来源坐标进入真实定位流程，保存当前正式应用、真实HTTPS瓦片、屏幕及构建记录。它比独立瓦片拼图更接近端到端，但仍没有源点测量精度；不得把测试accuracy=50当成GNSS实测精度。大陆/港澳候选加东京3点共13点两个精度结果均保留未证实。新增香港地政总署/IGS站日志是后续测量线索，Approximate Position(ITRF)的框架/历元与目标参考缺口未解决。

本轮不改变P05-R1的10m和200m标准。下一步须取得独立转换响应/参考坐标对、明确基准/历元和物理点精度；东京另外需要有地物的底图覆盖证据。最终判定由验收Agent完成。


## Tokyo basemap decision — 2026-09-14

东京GSI标准地图替代已证实返回纯色的高德style=8。catalog新增可选basemap枚举；P05 basemaps.ts是供应商URL/署名/显示坐标/zoom范围唯一归属。Tokyo明确gsi-standard，其他当前城市保持amap；缺省保持既有选择，无破坏性字段迁移、无兼容服务。spatialContext只决定P02源坐标资格，不承载瓦片覆盖或逐记录认证。所有空间消费者显式传递同一basemap，切换时释放旧实例。

GSI日本标准图z9–18与公开XYZ规则相符，署名“地理院タイル（国土地理院）”；FAQ Q1-12准许出典明示后直接在线读取。GSI规范称JGD2011，当前EPSG/PROJ说明2025后JGD2024水平定义/坐标不变。应用不加GCJ偏移；逆EPSG:9936公布1m的中低精度近似作为独立数值参考，而非高精度历元变换。

东京3点真实应用与12张跨缩放瓦片证明有地物；独立数值差值约0.0001m。另从GSI公开测绘图预先选定3个建筑轮廓顶点，以17.5m标准差、30m制图位移、1m基准操作及2px读点构造显式3σ工作预算，应用屏幕残差加预算约84.47m。此为对发布测绘图的校准，不能声称实地0m或独立复测GSI；最终口径由验收Agent判定。该轮取证原始输出已清理。大陆/港澳独立高德响应与物理参考仍缺，不降低10m/200m阈值。

扩城验收新增独立底图覆盖记录，真实应用检查地物/署名/缩放/点位对应，P07发布交接复核；HTTP200及mock回归不可替代。当前修复不将任意纯色图当服务故障，不更改P02名单或位置资格。
